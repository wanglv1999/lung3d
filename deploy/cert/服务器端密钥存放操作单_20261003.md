## 0. 为什么不能随便 `touch` 一个文件

这一步看着简单，但有**两个真实的泄露口**，所以下面的命令是有讲究的：

| 风险 | 说明 | 对策 |
|---|---|---|
| **权限窗口** | `touch` 建文件默认权限受 `umask` 影响（通常 `644`，同机其他用户可读）；即便随后 `chmod 600`，中间仍有一段"可读"时间 | 用 `install -m 600` **原子地**创建 600 空文件 |
| **命令历史** | `echo 'export DP_Key="abc..."' >> file` 会把**密钥明文写进 `~/.bash_history`** | 用 heredoc 或 `read -s`，密钥不作为命令行参数 |

记住这两条，下面两种写法就都安全了。

## 1. 登录服务器

```bash

```

已实测的现状：

- 22 端口**开放**，握手正常
- `root` 用户可用，服务器支持的认证方式：**`publickey,password`**（也就是**密码能直接登**，不必先配密钥）

## 2. 写入凭据（二选一）

### 方式 A · 交互输入（推荐，密钥全程不回显）

```bash
# ① 原子创建 600 空文件（权限从诞生那一刻就是 600，没有窗口期）
install -m 600 /dev/null /etc/ssl/.dnspod-env

# ② 交互式读取，-s 不回显
read -rsp "DP_Id : " _id; echo
read -rsp "DP_Key: " _key; echo

# ③ 写入（变量在展开后才落盘，命令行本身不含密钥）
printf 'export DP_Id="%s"\nexport DP_Key="%s"\n' "$_id" "$_key" > /etc/ssl/.dnspod-env

# ④ 抹掉 shell 里残留的临时变量
unset _id _key
```

好处：**密钥不会出现在屏幕上，也不会进历史**。

### 方式 B · heredoc 一次性写入（更省事）

```bash
install -m 600 /dev/null /etc/ssl/.dnspod-env

cat > /etc/ssl/.dnspod-env <<'EOF'
export DP_Id="123456"
export DP_Key="在此粘贴你的32位Token"
EOF
```

> heredoc 的内容**不属于命令行参数**，所以同样**不会进 `~/.bash_history`**。
> 注意 `<<'EOF'` 的**单引号别丢** —— 保证 `$` 等字符原样写入，不被 shell 展开。

### ❌ 不要这样写

```bash
echo 'export DP_Key="abcdef0123..."' >> /etc/ssl/.dnspod-env
```

密钥明文进 `~/.bash_history`，同机任何人 `cat ~/.bash_history` 就能看到。

### 方式 C · 本地生成、直接管道送入（不想在 ssh 里手敲）

在**本地 Git Bash** 执行，无需先登录：

```bash
ssh root@82.156.160.22 "install -m 600 /dev/null /etc/ssl/.dnspod-env && cat > /etc/ssl/.dnspod-env" <<'EOF'
export DP_Id="123456"
export DP_Key="你的Token"
EOF
```

（heredoc 同样不进本地历史；但密钥会在终端可见，注意周围没人。）

## 3. 验证（三条，10 秒）

```bash
# ① 权限必须恰好 600、属主 root
stat -c '%a %U:%G  %n' /etc/ssl/.dnspod-env
# 期望输出：600 root:root  /etc/ssl/.dnspod-env

# ② 能否正确加载（只打印长度，不打印密钥本身）
source /etc/ssl/.dnspod-env
[ -n "$DP_Id" ] && [ -n "$DP_Key" ] \
  && echo "OK 已加载（ID ${#DP_Id} 位 / Key ${#DP_Key} 位）" \
  || echo "FAIL 变量为空，检查文件内容"

# ③ 确认历史里没有残留
grep -c "DP_Key" ~/.bash_history 2>/dev/null || echo 0
# 期望 0
```

> 如果 ③ 不是 `0`，说明之前误用过 `echo` 方式，清理一下：
> ```bash
> sed -i '/DP_Key/d; /DP_Id/d' ~/.bash_history && history -c
> ```

## 4. 先自测密钥有效，再签证书

```bash
source /etc/ssl/.dnspod-env

curl -s -X POST https://dnsapi.cn/Domain.List \
  -d "login_token=${DP_Id},${DP_Key}" \
  -d "format=json" | head -c 500
```

| 返回 | 含义 |
|---|---|
| `"code":"1"`，且列表内含 `tdyylung3d.cn` | ✅ 密钥有效，可以签发 |
| `"code":"3"` / `"code":"4"` | 密钥错，或 ID / Token 填反了 |
| 权限不足 / 域名不在列表 | 创建密钥时勾的域名范围没包含它，回去重配 |

这条请求**只列域名、不改任何解析记录**，随便跑。

## 5. 以后怎么用（关键习惯）

```bash
source /etc/ssl/.dnspod-env
bash deploy/cert/issue_cert_dnspod.sh
```

> ⚠️ **永远用 `source`，不要直接敲 `export DP_Id=...`**。
> 直接 export 会把密钥明文写进历史 —— 这正是当初把凭据放进这个文件的意义。
>
> acme.sh 首次签发成功后，会自动把两个值存进 `~/.acme.sh/account.conf`（键名 `SAVED_DP_Id` / `SAVED_DP_Key`），**之后的自动续期直接复用，不用再 source**。这个文件主要服务于"首次签发"和"将来重建环境"。

## 6. 想换或想删

```bash
# 换密钥：重新走一遍第 2 步（覆盖写入即可，权限不变）
# 彻底删除：
shred -u /etc/ssl/.dnspod-env 2>/dev/null || rm -f /etc/ssl/.dnspod-env
```

换了密钥后记得同步删掉旧的 `SAVED_DP_Id` / `SAVED_DP_Key`：

```bash
sed -i '/SAVED_DP_Id/d; /SAVED_DP_Key/d' ~/.acme.sh/account.conf
```

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| `install: cannot create regular file: No such file or directory` | `/etc/ssl` 不存在（极罕见）。先 `sudo mkdir -p /etc/ssl && sudo chmod 755 /etc/ssl` |
| `stat` 显示 `644` 或 `664` | 重跑 `chmod 600 /etc/ssl/.dnspod-env`，并检查是否被人改过 |
| 登录用户不是 root，命令全报权限不足 | 每条命令前加 `sudo`；或直接改登 root |
| 用 `vim` 编辑过该文件 | 删掉残留交换文件 `rm -f /etc/ssl/.swp /etc/ssl/.*.swp`；并且 vim 会把内容写进 `~/.viminfo` —— 改用 heredoc 重建 |
| 密钥粘贴时多了空格/换行 | 重跑验证第 ② 步看长度：`DP_Id` 通常 5~8 位数字，`DP_Key` 恰好 32 位 |
