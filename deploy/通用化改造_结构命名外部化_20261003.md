### 后端关键实现

- `parse_label_config(path)` —— 解析标注配置，返回 `{"by_label": {标签值: 结构}, "by_key": {键名: 结构}}`
- `load_label_config(*roots)` —— 依次在给定目录（upload / 解压目录 / case 目录）查找 `labels.json`、`structures.json`，
  再回退到环境变量 `STRUCTURE_LABELS` 指定的外部文件；全都没有时返回空配置
- `default_structure_name(key)` —— `label_3` → `结构 3`；其余（由文件名派生的键）原样使用
- 原针对医学键名的**特殊网格参数改为按 `role` 字段声明**：
  - `role: "vessel"` → 按管径阈值剪除远端细支（原 `lung_arteries` / `lung_veins`）
  - `role: "wall"` → 单独降采样且不做平滑（原 `lung_airways_wall`）
  - 其余 → 普通结构处理

## 三、`labels.json` 契约

放在数据目录根（与 `combined.nii.gz` 同级），随数据一起被上传/分发：

```json
{
  "schema": "lung3d.labels/1",
  "structures": [
    {"label": 1, "key": "lung_arteries",     "name": "肺动脉",     "color": [1.0, 0.2, 0.2], "role": "vessel"},
    {"label": 2, "key": "lung_veins",        "name": "肺静脉",     "color": [0.2, 0.4, 1.0], "role": "vessel"},
    {"label": 3, "key": "lung_airways",      "name": "气管支气管", "color": [0.2, 1.0, 0.3], "role": "airway"},
    {"label": 4, "key": "lung_airways_wall", "name": "气道壁",     "color": [0.9, 0.6, 0.2], "role": "wall"},
    {"label": 5, "key": "lung_nodules",      "name": "肺结节",     "color": [1.0, 1.0, 0.1], "role": "lesion"}
  ]
}
```

- `label` 可省略，缺省按列表顺序取 1、2、3…
- `color` 可省略 → 查看端从内置调色板自动分配
- `role` 可省略 → 按普通结构处理
- 只声明部分标签时，未声明的回退为「结构 N」

## 五、对现有数据与线上环境的影响（重要）

1. **已存在的 case 不受影响**：历史 `report.json` 里已经写死了结构名，接口直接回读，
   仍会显示肺动脉等名称。它们是**运维方自己的存量数据**，不是查看端内置词汇。
2. **新建 case 的命名取决于随数据上传的 `labels.json`**：
   - 上传**数据目录 zip**（桌面工具新版本产出，内含 `labels.json`）→ 名称与配色照旧；
   - 只上传**裸 `combined.nii.gz`**（不带 `labels.json`）→ 显示为「结构 1…5」。
3. **桌面工具需重新跑一遍**，才会产出带 `labels.json` 的数据目录；
   此前已产出的数据目录没有该文件，建议补跑或手工补一个 `labels.json`。
