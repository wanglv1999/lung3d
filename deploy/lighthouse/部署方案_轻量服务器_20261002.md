# 腾讯云轻量应用服务器（境内 2核2G）部署方案

> 目标：把 Lung3D 小程序后端从「微信云托管」迁到「轻量应用服务器」，顺带解决**数据不持久**与**冷启动 503** 两个隐患。
> 本文档为**方案稿**，未对线上做任何改动。所有配置文件已备好放在本目录，确认后再执行。

- 编制时间：2026-10-02
- 适用机型：腾讯云轻量应用服务器，**境内节点**，**2核2G**（典型配 4M 峰值带宽 / 50GB SSD / 300GB 月流量）
- 现状：后端跑在微信云托管 / CloudBase Run，域名 `https://tdyylung3d.cn`

---

## 0. 适用性判定

| 判定项 | 结论 | 说明 |
|---|---|---|
| 能否用于小程序 | ✅ **可以** | 境内节点可正常 ICP 备案，满足微信硬要求 |
| 是否需改小程序代码 | ❌ **不需要** | 域名不变，只需改 DNS 解析 |
| 能否解决数据丢失 | ✅ **可以** | 病例落本地 SSD，重启不丢 |
| 能否解决冷启动 | ✅ **可以** | 服务常驻，无缩容到 0 |
| 主要代价 | ⚠️ 带宽小、内存紧、需自己运维 | 见第 4、5、7 节 |

**一句话**：可行，且是当前最直接的"一石二鸟"方案；难点全在 2核2G 这个规格的资源调优与带宽体验上。

## 1. 前置条件核对清单（4 项，缺一不可）

| # | 条件 | 要求 | 如何确认 |
|---|---|---|---|
| 1 | **ICP 备案** | 域名必须已备案且在有效期内 | 工信部备案系统 / 腾讯云控制台「备案」查询 |
| 2 | **主体一致** | 备案主体 = 小程序认证主体 | 不一致会被微信校验拦截 |
| 3 | **HTTPS 证书** | TLS 1.2+，证书链完整，有效期 > 3 个月 | 已有 TrustAsia DV 证书（见第 6 节，**11-30 到期**） |
| 4 | **安全组** | 放行 80 / 443 / 22 | 轻量控制台「防火墙」 |

> ⚠️ **最关键的是第 1、2 项**。`tdyylung3d.cn` 目前挂在云托管上（境内云托管自定义域名本就要求备案），大概率已备案；但迁到轻量属于**更换接入服务器**，建议先在腾讯云备案控制台确认状态，必要时做「接入信息变更」。**这一步没确认前，不要动 DNS。**

## 2. 目标架构

```
                     ┌───────────────────────┐
   微信小程序 ───────▶│  tdyylung3d.cn :443    │
   网页版浏览器 ─────▶│  nginx（TLS + 反代）   │  轻量应用服务器 2核2G
                     └───────────┬───────────┘
                                 │ 127.0.0.1:8000
                     ┌───────────▼───────────┐
                     │  lung3d-web 容器       │
                     │  FastAPI lung3d_api.py │
                     └───────────┬───────────┘
                                 │ 挂载卷
                     ┌───────────▼───────────┐
                     │  /data/lung3d/cases    │  本地 SSD 持久盘
                     └───────────────────────┘
```

要点：
- nginx 负责 TLS 终止与静态资源缓存，fastapi 只监听 `127.0.0.1:8000`，**不对外暴露 8000 端口**。
- 病例目录从容器内 `/app/web_output/cases` 挂载到宿主机 `/data/lung3d/cases` → 容器重建、升级都不丢数据。
- 与现状唯一的对外差异：DNS A 记录从云托管 IP 改成本机公网 IP。

## 3. 部署步骤（逐步）

### Step 0 · 服务器初始化
```bash
# 以 root 登录（或在命令前加 sudo）
bash setup_server.sh          # 本目录已备好，做：装 Docker、建目录、配 swap、装 acme.sh
```
> ⚠️ 上传到 Linux 后先处理换行符，否则脚本报 `bad interpreter`：
> ```bash
> sed -i 's/\r$//' setup_server.sh && chmod +x setup_server.sh
> ```

### Step 1 · 准备镜像
两种来源，任选：
```bash
# 方式 A：从腾讯云镜像仓库（同地域内网拉取，快且不计流量）
docker login ccr.ccs.tencentyun.com -u <用户名>
docker pull ccr.ccs.tencentyun.com/<命名空间>/<服务名>:latest

# 方式 B：从 Docker Hub
docker login -u <用户名>
docker pull <用户名>/lung3d-web:latest
```

### Step 2 · 配置环境变量
```bash
cp .env.example .env
vi .env        # 填入 WX_APPID / WX_SECRET 等（.env 不要提交 git）
```

### Step 3 · 启动后端容器
```bash
docker compose up -d
docker compose logs -f          # 看到 "Lung3D API: http://0.0.0.0:8000" 即成功
curl http://127.0.0.1:8000/api/health     # -> {"status":"ok"}
```

### Step 4 · 配置 nginx 与证书
```bash
# 证书（先用已有 TrustAsia 证书，或直接上 acme.sh 自动签发，二选一）
mkdir -p /etc/nginx/ssl
cp tdyylung3d.cn_bundle.crt /etc/nginx/ssl/tdyylung3d.cn.crt
cp tdyylung3d.cn.key        /etc/nginx/ssl/tdyylung3d.cn.key
chmod 600 /etc/nginx/ssl/tdyylung3d.cn.key

cp nginx/lung3d.conf /etc/nginx/conf.d/lung3d.conf
nginx -t && systemctl reload nginx
```

### Step 5 · 切换 DNS（**最后一步，且可回滚**）
```
轻量控制台查到公网 IP  →  域名解析处把 tdyylung3d.cn 的 A 记录改指向该 IP
```
- CloudBase 是 CNAME 解析，需**先删除原 CNAME，再新增 A 记录**。
- 生效后小程序、网页端**无需任何改动**。

### Step 6 · 验证
```bash
curl https://tdyylung3d.cn/api/health
curl -X POST -F "files=@样例.nii.gz" -F "name=迁移验证" https://tdyylung3d.cn/api/process
# 轮询 /api/case/{id}，再下载 /api/mesh/{id}/*.glb
```

### Step 7 · 回滚预案
一旦异常，**把 A 记录改回云托管 CNAME 即可**，云托管服务保持不动作为后备。
> 建议：迁移后**至少保留云托管一周**再考虑下线，期间随时可切回。

## 4. 2核2G 专项调优（本方案重点）

2 核 2G 跑网格提取（`marching_cubes` + Taubin 平滑）**内存是最大风险**。以下参数已在 `.env.example` 与 `docker-compose.yml` 中预设：

| 参数 | 建议值 | 作用 |
|---|---|---|
| `MESH_DS_FACTOR` | `3` | 网格降采样系数，**数值越大内存/耗时越低**（质量略降） |
| `WALL_DS_FACTOR` | `4` | 气道壁单独再降一档 |
| `MAX_CONCURRENT_PROCESSING` | `1` | 串行处理，防并发 OOM（保持默认） |
| `DISTAL_PRUNE_MM` | `1.0` | 剪除更细的远端血管，减小网格体积 |
| `CASE_EXPIRE_DAYS` | `30` | 本地盘没有"临时"顾虑，可放宽自动清理周期 |
| 容器内存上限 | `1536m` | compose 中限制，避免把宿主机拖死 |
| **Swap** | **2GB** | `setup_server.sh` 已配，OOM 时兜底 |

> 💡 若处理较大 CT 时仍 OOM：把 `MESH_DS_FACTOR` 调到 4，并确认 swap 生效（`free -h`）。
> 💡 若这台 2核2G 是"活动机型不支持升降配"：后续确实不够，只能重购更高规格，**先把上面的调优用满**。

## 5. 带宽与流量优化（体验瓶颈）

实测单个 GLB 可达 **2.97MB**，一个病例 5~6 个结构合计约 **10~30MB**。4M 峰值带宽 ≈ 500KB/s，单病例首屏可能需 30s+。

**流量够用**（工程量测算）：

| 项 | 数值 |
|---|---|
| 月流量额度 | 300 GB |
| 单病例下载量 | 约 15 MB（估） |
| 理论可支撑浏览 | 约 20,000 次/月 |

结论：**流量不是问题，带宽峰值才是。** 优化手段按性价比排序：

1. **降低网格体量**（最有效）：调大 `MESH_DS_FACTOR`、提高 `DISTAL_PRUNE_MM`，从源头把 GLB 做小。
2. **nginx 开启 gzip + HTTP/2**：已写入 `nginx/lung3d.conf`。
3. **GLB 走 Draco 压缩**：可再减 60~80%，但需前后端同时改动（小程序端 gltf-loader 要支持），列为**二期优化**。
4. **CDN 加速**：病例 GLB 属静态资源，后续可挂腾讯云 CDN，注意**回源要隐藏真实 IP**（写 CDN 回源鉴权），避免触发微信安全拦截。

## 6. 证书与自动续期

- 现有证书：`tdyylung3d.cn_nginx/tdyylung3d.cn_bundle.crt`（TrustAsia DV，覆盖 `tdyylung3d.cn` + `www.tdyylung3d.cn`）
- **有效期：2026-09-01 → 2026-11-30（仅 90 天）**，crt 与 key 已验证匹配。
- 风险：**11-30 到期，手工续期容易漏**。到期后小程序所有请求会直接失败。

**推荐做法**：改用 **acme.sh + Let's Encrypt 自动续期**（`setup_server.sh` 已装 acme.sh）：
```bash
acme.sh --issue -d tdyylung3d.cn -d www.tdyylung3d.cn --nginx
acme.sh --install-cert -d tdyylung3d.cn \
  --key-file       /etc/nginx/ssl/tdyylung3d.cn.key \
  --fullchain-file /etc/nginx/ssl/tdyylung3d.cn.crt \
  --reloadcmd      "systemctl reload nginx"
```
> 微信要求"证书有效期 > 3 个月"——Let's Encrypt 是 90 天但**自动续期后始终满足**，比手工 90 天证书稳。
